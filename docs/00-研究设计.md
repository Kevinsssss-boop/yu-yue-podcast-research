## 三、研究范围与字段清单 ★ 最关键

### 3.1 操作定义（先定边界，再定字段）

**入选标准（唯一一条，决定"采不采"）**：

> **内容是主要用粤语讲的。** —— 只看**语言**，不看主题。

**判定规则（2026-10-16 定稿，一条规则说清）**：

> 读 4 个字段 —— **节目名 + 节目简介 + 主播 + 平台/版权** —— 找「粤语标志物」。
> **命中任意一个 → 判【粤语】；都没命中 → 判【非粤语】。**

| 标志物类别 | 具体内容 | 例 |
|-----------|---------|-----|
| **A 类 · 显式声明** | `粤语` `粵語` `粤語` `廣東話` `广东话` `Cantonese` `Cantonés` | 「【粤语】得闲饮茶」／主播「BBC **Cantonese** Radio」 |
| **B 类 · 粤语特有字** | `嘅 咁 係 喺 唔 嗰 啲 嘢 乜 睇 冇 咗 哋 佢 畀 嚟 喇 吓 啩 啰 嘞 噉 咪 咩` | 「**是咁的**…｜廣東話Podcast」／「**開show喇**！」 |

**辅助信号（不作单独判定，用于缩小人工范围）**：

| 信号 | 用法 | 实测 |
|------|------|------|
| **单集标题有粤语信号** | 用于**待复核**那一堆的二次判定 | 81 个待复核里救回 **5 个**（如「澳門癲台」593/1212 集含粤语） |
| **反向标志**（`台語` `閩南` `客家` `講客` `世新` `普通话`） | 批量确认为**非粤语** | 锁定 18 个 |
| **0 集** | 判定为**坏数据**，直接剔除 | 3 个 |

> ⚠️ **代理的代价**：会有**假阳性**（标题带"广东"却无关）、**假阴性**（真粤语节目标题没写"粤语"）。
> 对策：**拿不准的先全采**，`语言` 列标 `不确定`，事后抽样人工听。
>
> ⚠️ **已实测失败的判据（别再试）**：用「单集标题含粤语字的比例」当筛子 —— 高置信档（≥30%）确实准，
> 但**零档的 139 个里全是真粤语节目**（粤语节目的单集标题也常用书面语，如「创世记 第一章」）。
> 结论：**粤语性只体现在节目级元数据里，单集层面看不出来。**

**分析维度（不决定采不采，只决定怎么分析）**：

| 维度 | 取值 | 来源 |
|------|------|------|
| **语言** | 粤语 / 不确定 / 非粤语 | 元数据代理 + 人工复核 |
| **内容形态** | 谈话访谈 / 语言教学 / 有声书 / 虚构叙事 / 宗教 / 儿童 / 音乐 / 新闻 / 真实犯罪 | **①官方分类映射**（446/450 有）+ 人工复核 |
| **主题** | 语言学习 / 文化历史 / 生活情感 / 时事社会 / 音乐娱乐 / … | ①官方分类 ②AI 初标 ③人工终标 |

### 3.1.1 ⚠️ 为什么要加「内容形态」这个维度（2026-10-16 关键决定）

**问题**：我们用苹果目录当抽样框，而苹果把**有声书、广播剧、讲道**也当播客收录。
实测 450 个节目的形态分布：

| 形态 | 节目数 | 单集数 |
|------|:---:|:---:|
| **谈话/访谈类** | **185（41%）** | 16,552（32%） |
| 虚构叙事 / 有声书 | 90（20%） | 5,969（12%） |
| 语言教学 | 52（12%） | 8,324（16%） |
| 宗教（讲道/诵读） | 35（8%） | 6,836（13%） |
| 非语言教育 | 31（7%） | 3,208（6%） |
| 儿童/音乐/真实犯罪/新闻 | 53（12%） | 9,532（19%） |

**谈话类只占 41%**，其余 59% 是「粤语有声内容」，不是「粤语谈话播客」。典型样例：

```
「Fiction」类：轮回劫：花若殇【粤语】古风玄幻言情小说（107集）
             缥缈|粤语女声|东方奇幻|聊斋神狐志怪（431集）
             《重煉傳說》（原文粵語朗讀）（300集）
「Books」类：  聖嚴法師有聲書 (粵語版)（193集）
             金瓶梅（女频粤语演绎）（36集）
```

**三个后果**：

1. **主题分布会失真**——LDA 会跑出「玄幻/言情/修仙」这类**小说题材**，和「社会/生活/时事」这类**节目话题**混在一起，不可比
2. **分析单位不一致**——谈话播客一集=一个话题，有声小说一集=一章，教学一集=一课；按单集做词频会被高产有声书主导
3. **交叉印证失去意义**——内容侧被小说题材拉偏，听众侧评论聊的是剧情，供需对比无从谈起

**对策（方案 B）：全保留 + 按形态分层**

- **入选标准不变**（只看语言）——广播剧只要是粤语就**留**
- **分析时分层**——`内容形态` 作为独立变量
- **主分析（主题分布、供需印证）只在「谈话/访谈」子集上做**；其他形态**另行描述**
- **「形态分布」本身就是生态图谱的一个发现**，不是要清洗掉的噪声

> 💡 两个变量各管一件事：**入选看语言，分析看形态**。逻辑不冲突。
>
> 💡 **为什么不用"体裁"直接剔除广播剧**：那等于事后改入选标准，面试被追问很难解释。
> 用"语言"筛掉它们，和用"体裁"筛掉，性质完全不同。

### 3.1.2 播客的定义（报告里要写）

**技术层（刚性）**：
> 播客 = 通过**开放 RSS** 发布、可被客户端**自动订阅下载**的音频内容。
> 三要件：`有 RSS feed` + `每集有 enclosure 指向音频` + `持续更新`。

与相邻概念的边界：

| | 播客 | 音乐流媒体 | 有声书 App | 广播电台 |
|---|---|---|---|---|
| 分发 | **开放 RSS** | 平台私有 | 平台私有 | 空中广播 |
| 订阅 | 客户端**自动下载**新集 | 平台内歌单 | 买断/会员 | 无 |
| 谁能发行 | **任何人** | 唱片公司 | 出版社 | 持牌电台 |

**内容层（弹性）**：
> 播客是一种**媒介（medium）**，不是**体裁（genre）**——就像"电视频道"里可以有新闻、电视剧、综艺。
> 证据：Apple Podcasts 分类体系里就有 `Fiction / Drama`、`Comedy Fiction`、`Science Fiction`。

**本研究的操作性定义**：
> **采用苹果播客目录的定义**——凡出现在 `itunes.apple.com/search?entity=podcast`
> 结果里的即为播客。这就是本研究的**抽样框（sampling frame）**。

### 后羿试采 10 条的统一步骤

> 按钮名可能和你实际界面略有差异，以实际为准；核心流程是一样的。

1. **新建采集任务** → 选择「**智能模式**」（自动识别列表页）
2. 把目标页面网址粘进去（先只测**一个列表页**，别急着配翻页）
3. 等它自动识别出列表 → 看**预览**里能不能对上
4. **手动点选要采集的字段** → 按第三节字段清单逐个人工指定（智能模式识别不全，通常要补）
5. **翻页设置**：先看它自动识别到什么（分页按钮 / 滚动加载）
6. 需要登录的平台：用「**预登录**」手动登录一次
7. **试运行** → 看前 10 条结果对不对 → 导出 Excel/CSV

### 六个必须当场记下的坑

| 坑                                 | 应对                                                                      |
| ---------------------------------- | ------------------------------------------------------------------------- |
| **不要开「加速引擎」**       | 开了反而被判异常频率、封 IP。慢一点反而稳定                               |
| 采集器**不自动保存**         | 每改完一段字段名就**手动保存**一次，否则切页面全丢                  |
| 字段**偏移**（值在但位置错） | 检查每列取值范围是否合理，比如「点赞数」列里出现「2024-01-01」就是错位    |
| 评论**懒加载**               | 要滚动到底才能加载全部，可能需要设置「滚动加载」而不是「点下一页」        |
| 数字带单位                         | 「1.2万」「10w+」——原样导出，清洗阶段再转数字                           |
| 时间格式乱                         | 相对时间（「3天前」「昨天」）——原样导出，**记下采集日期**以便换算 |

## 五、⚠️ 粤语特有的四个坑（清洗/分析前必读）

| # | 坑                         | 表现                                                      | 应对                                                          |
| - | -------------------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| 1 | **繁简混杂**         | 香港用繁体「廣東話」，广东用简体「广东话」，被当成两个词  | OpenCC 统一成简体                                             |
| 2 | **jieba 不适配粤语** | 粤语口语词被切碎                                          | 加载自定义词典（可从数据里高频未知词反推）                    |
| 3 | **粤语特有字**       | 嘅、咁、係、喺、唔、嗰、啲、嘢、乜、睇、冇、咗… 自带语义 | 加进自定义词典，别当停用词删                                  |
| 4 | **情感分析不准**     | SnowNLP / 原项目 BERT 点评模型都是普通话语料              | 探索阶段用**粤语词典法 + 人工抽检**，报告里如实标注局限 |

### 5.1 ⚠️ 采集阶段的坑（2026-10-15 实测）

| # | 坑 | 表现 | 应对 |
|---|----|------|------|
| 1 | **苹果搜索索引 ≠ RSS 元数据** | 「见面倾啦」的 RSS 简介明写"粤语播客"，但搜「粤语」**翻到 200 条也搜不到它**；改搜「栋笃笑」**立刻排第 1**。推断苹果搜的是自己收录的那份元数据，和 RSS 里的 `description` 不是同一份（小宇宙托管的节目尤其明显） | **关键词要加"圈层词"**（栋笃笑/粤剧/港乐/广东歌/港片…），即圈内人怎么自称。另外用 `SEED_FEEDS` 人工兜底 |
| 2 | **通名 vs 圈层词** | 节目作者不会写"我是粤语播客"，他会写"我讲栋笃笑"。**用通名搜圈内人，必然漏** | 见上。种子节目 → 翻简介找行话 → 再搜 → 滚雪球 |
| 3 | **扩大关键词 ≠ 提高覆盖率** | 实测：加"香港/港式/广州"等地域词，净增 558 个候选，但**干净率只有 5%**（现有 435 个是 77%）；而"名字含粤语口语字"这个零成本筛子，精度 **≈100%**（14/14 全中） | **宁可精准补 15 个，不要脏的 800 个**。补漏的价值在"补系统性偏差"（现有 435 全是"自称粤语"的），不在数量 |
| 4 | **`entity=podcastEpisode`** | 搜索接口的参数。`podcast` = 在「节目名+节目简介」里搜，`podcastEpisode` = 在「单集标题+单集简介」里搜。很多节目的**简介没写粤语、但某一集标题写了** | 要扩大召回时改这个参数。返回的每条**照样带 `feedUrl`**，后续代码不用改 |
| 5 | **电台类"空壳 feed"** | RTHK 的 `830_teaser_i.xml` 只有 `<channel>`、**0 个 `<item>`**，解析出 0 集。苹果给的地址就是错的 | 采集脚本已加保险：**采到 0 集就报警**并记进失败清单，不静默 |

### 8.5 ⚠️ 繁简转换的技术坑与解法 ★

**问题**：OpenCC 的 `t2s` 是**为普通话设计的**，套到粤语上会改坏字。实测 51 个粤语字里有 **8 个被改**：

| 原字 | 被转成 | 后果 |
| :--: | :----: | ---- |
| **嗰** | 𠮶（U+20BB6） | 扩展 B 区异体字，字体显示成方框、分词切错 |
| **餸** | 𩠌（U+2980C） | 同上（粤语「买餸」） |
| **孻** | 𡥧（U+21967） | 同上（粤语「孻仔」） |
| **躝** | 𨅬（U+2816C） | 同上（粤语「躝开」） |
| **癐** | 𤶊（U+24D8A） | 同上 |
| **係** | 系 | **语义混淆**：「係」是粤语"是"，「系」是"系统/关系" |
| 囉 / 撳 | 啰 / 揿 | 可接受（正确繁简对应） |

**为什么不用"手写保护清单"**：我最初只想保护 `嗰`，实测还有 `餸`/`孻`/`躝`/`癐`/`𨋢`——
**手写必然漏，而且判据主观、要长期维护**。

**最终解法：自动识别 + 转换后回填**（实现在 `cy_utils.cantonese_t2s()`）

```
① 建表（只建一次，0.20 秒）
   扫 CJK 三个区：基本区 U+4E00–9FFF / 扩展A U+3400–4DBF / 扩展B U+20000–2A6DF
   对每个字做 t2s，如果结果掉进「扩展 A / 扩展 B」→ 记下 反向映射
   共得到 1,245 条：𠮶→嗰、𩠌→餸、𡥧→孻、𨅬→躝、䢂→𨋢 …

② 转换（每次调用）
   转换前：只保护「係」（唯一有语义歧义的）
        ↓ OpenCC t2s
   转换后：translate 一次扫完，把生僻字全换回来
        ↓
   结果
```

**为什么只有 `係` 需要"转换前保护"**：因为 `𠮶` 这类**反向映射是唯一的**（`𠮶` 只可能来自 `嗰`），
转换完直接换回去即可，不需要占位符；而 `系` 有歧义，只能在转换前拦。

**实测效果**：

| 指标 | 数值 |
| ---- | ---- |
| 自动发现的映射 | **1,245 条**（基本区 710 + 扩展A 190 + 扩展B 347） |
| 建表耗时 | **0.20 秒** |
| 处理全库 | 102,064 个字段 / **56.9 秒** |
| 转换新造的生僻字 | **2 个**（占 0.002%，已知残留，接受） |

**效果对照**：

| 原句 | 转换后 |
| ---- | ------ |
| 呢個節目真係好聽，我哋一齊聽下 | 呢个节目真**係**好听，我哋一齐听下 |
| 嗰間舖頭嘅嘢好正 | **嗰**间舖头嘅嘢好正 |
| 買餸、孻仔、躝開啦 | 买**餸**、**孻**仔、**躝**开啦 |
| 呢個係系統嘅問題 | 呢个**係**系统嘅问题 |

> 📌 **顺带的发现**：原文里本来就有 **802 个生僻字（83 种）**，几乎全是粤语词：
> 㗎 507 次、㖞 70 次、㩒 39 次、𥚃 17 次、䓝 15 次、𨋢 14 次（粤语"电梯"）。
> **这是数据真实性的旁证**——这些字只出现在粤语文本里。
